# 安装包开发与验证

## v0.25 当前发行流程（内部版本 0.2.5.5）

以下历史测试记录只适用于对应旧构建。当前安装包的集成测试结论以 `release/TEST-REPORT.md` 及其中的 SHA-256 为准。

附带媒体由 GitHub Release 单独提供，未放入 Git 历史。首次构建先执行 `installer/Download-BundledMedia.ps1` 下载并校验，来源说明见 `assets/MEDIA-NOTICE.txt`。

在 Windows x64 的 Windows PowerShell 5.1 中运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File installer/Build-Release.ps1
```

构建使用 .NET Framework 自带 C# 编译器、WPF 和系统 PowerShell，不要求 .NET SDK。脚本先构建并运行隔离测试，再生成 `release/BootStudio_Setup.exe`、用户说明、许可证、隔离测试记录、构建信息及 SHA256SUMS.txt。所有输出均在开发目录中；此命令不安装应用，也不更改宿主机 Shell。不要在测试完成后重新构建并沿用旧测试结论：每次构建都会把集成测试报告重置为待验证。

安装包包含独立 `Uninstall.exe`、启动恢复脚本、文件删除边界检查及生成的 6 秒测试视频。新版卸载先恢复并独立核验启动状态，再删除整个安装目录（含导入副本、配置和日志）、本应用快捷方式及卸载登记。启动状态不明确、文件占用或目录包含重解析点时停止删除。不会删除用户的源视频。

发布前必须用最终安装包完成以下记录：干净虚拟机安装及配置、打开应用、预览、导入和切换视频、实际登录可见播放、正常回到桌面、从 Windows 应用列表卸载、确认文件和启动入口清理、再次登录正常进入桌面、卸载后重新安装。记录系统版本、安装包散列、实际屏幕观察和日志；媒体日志正常不能代替画面验证。Windows 10/11 应分别注明已测或未测。

发布时保持经过验证的 EXE 不变，更新 TEST-REPORT.md，核对 SHA256SUMS.txt，再分发 release 目录。签名证书尚未配置，当前是未签名测试版；不可写成全部环境已验证。当前附带经提供者确认授权的《新宿决战·雨爱版》及生成测试图，不打包本机备份、私人视频库或账号信息。GitHub 发布是单独步骤，构建脚本不会自动上传。

## 历史实现与验证记录

`Build-Package.ps1 -Test` 从允许的文件清单构建单文件安装程序，输出到 `dist`。不读取当前运行配置、视频库、本机备份或自动登录凭据。应用构建输出到临时包目录，不覆盖现有 `app/bin`。

`Test-Package.ps1` 在 `test-results` 中解包并校验文件，再用独立 JSON 后端测试启动事务。模拟后端不访问 Windows 注册表或任务计划程序。测试目录与构建产物不提交 Git。

## 结构

- `Setup.cs`：许可界面、运行环境检查、解包校验、开始菜单入口及卸载登记。
- `runtime/BootShell.cs`：安装版入口；播放器最多等待 180 秒；按登录会话恢复 Explorer。
- `runtime/Startup.Core.psm1`：当前用户 Shell 备份、恢复任务、启用和关闭事务。拒绝已有自定义 Shell 与受管理策略。
- `runtime/Invoke-Startup.ps1`：通过当前用户交互任务执行；之后通过另一个任务核对登录环境。所有任务使用 Limited 权限，不需要保存账号密码。
- `runtime/Restore-Desktop.ps1`：独立登录恢复保护。
- `Uninstall.cs`、`runtime/Uninstall.ps1`、`runtime/Removal.Core.psm1`：新版独立卸载入口、启动恢复核验及完整目录清理；旧版保留数据的行为见历史记录。

启动播放器脚本从原项目复制，通过 `Prepare-Player.ps1` 仅对包内版本加入当前会话 Explorer 检查、窗口就绪检查、阶段日志及媒体资源释放。`runtime/Player.WindowState.psm1` 要求窗口所在桌面已激活、窗口可见且句柄有效；手动模式还要求前台焦点。原运行目录的脚本和 BootShell 未替换。安装版默认关闭 Wallpaper Engine 联动和桌面图标/任务栏隐藏设置，使用 WPF 全屏视频。

已验证：构建、应用数据操作测试、包文件 SHA-256、干净目录解包、脚本解析、模拟启用/关闭及冲突和失败恢复。界面可打开，许可与配置选项可见。

2026-10-10：在本机真实登录任务中验证了只读状态通信，原项目的 Shell 未替换，原恢复任务仍正常。修正失败原因分类、模块加载错误反馈、请求过期/取消保护及许可文本换行；模拟过期和取消请求均未改变启动状态。

2026-10-10：干净 Windows 11 虚拟机中，0.2.1 的文件安装完成，但启动配置报 `Desktop recovery task verification failed`。0.2.2 将恢复任务的账号名称解析为 SID 后核对身份，保留恢复失败即回退的行为，并用真实 Windows 账号名称/SID 别名验证校验函数。

0.2.2 在干净虚拟机真实启用成功，独立登录任务验证 Enabled=true、Recovery=true；视频导入和预览成功。用户确认重启后先播放动画再出现桌面，但日志显示播放器触发了 55 秒安全期限。0.2.3 在包内播放器清理中关闭媒体源、关闭独立 WPF Dispatcher，并加入启动、媒体打开、关闭原因及进程退出日志；保留 55 秒超时保护，等待真实验证。

尚未验证：真实关闭事务、实际卸载、其他 Windows 版本/电脑和多账号运行。当前版本为 `0.2.5-preview`，不标记为正式发布版本。原 0.2.0 的超时日志没有足够状态信息，无法确认当时的超时根因。

0.2.3 第三轮冷启动后，用户更正反馈为没有播放画面。实际 boot-player.log 记录 Script started、Native helpers loaded、Opening overlay、Overlay rendered，但没有 Playback started 或 Media opened；播放器停在要求前台焦点的条件。0.2.4 增加窗口就绪检查：Shell 模式的窗口可见且有有效句柄时开始播放；手动模式保留前台要求。已增加焦点被其他窗口持有、不可见与无句柄场景的回归检查。

0.2.4 从干净 Windows 11 虚拟机安装，启动入口配置和 15 秒视频导入成功。正常关机后冷启动并登录，真实日志记录 Playback started、Media opened、Closing overlay: end、Player cleanup complete；BootShell 记录 Player exited with code 0，约 22 秒结束整个启动播放器流程，未触发 55 秒保护，桌面正常返回。但用户在下一次冷启动观察中明确反馈没有画面，因此不能将媒体日志正常视为屏幕播放通过。0.2.4 快照仅为诊断现场，尚不是可用画面基线。此前 0.2.2 用户确认过可见动画先于桌面，但存在 55 秒超时，两项问题需分别验证。

当前版本发现已有安装目录时停止，不提供升级。缺少 .NET Framework 4.8 时说明依赖和微软官方下载地址，不自动下载安装依赖。不设置自动登录、不改账号密码、不修改整机 Shell 或策略，不覆盖登录界面。未申请数字签名证书。
